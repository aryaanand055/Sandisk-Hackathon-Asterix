1. Problem Statement & Motivation

In modern semiconductor and ASIC verification, nightly regressions generate millions of lines of unstructured simulation logs. When runs fail, verification engineers face four severe triage bottlenecks:

⚠️ The "What" vs. "Why" Dilemma

A failed UVM test logs that an assertion fired or FIFO overflowed, but fails to explain which combination of configuration knobs triggered the failure state.

🎲 Flake vs. RTL Bug Conflation

Random seed-induced noise and hard deterministic RTL bugs emit similar UVM error reports, forcing engineers into days of tedious interactive waveform debugging.

📉 Black-Box Performance Tuning

Configuration tuning remains folklore. Verification leads lack tools to determine the fastest configuration settings that provably satisfy a failure budget (e.g., ≤ 2%).

🗑️ Ad-Hoc, Non-Accumulating Triage

Custom triage scripts are written per debug emergency and discarded immediately after. Verification knowledge never accumulates systematically across builds.

3. Key Technical Innovations

1. Leakage-Guarded Risk Modeling

Trained with LightGBM on only settable configuration knobs. All outcome variables (execution_time_ms, throughput_mbps, uvm_error_count, tags) and identifiers (run_id, seed) are strictly pruned, preventing artificial label leakage. SHAP TreeExplainer delivers directional attribution per feature value.

2. Determinism Scoring Engine

Masks dynamic fields (addresses → <ADDR>, values → <N>) and fits TF-IDF across unique templates. Collapses 50k logs into ~7 clusters. Defines:
Determinism = 1 - (Distinct Raw Traces / Total Cluster Runs).
Isolates true RTL bugs (score 0.999) from random flakes (score 0.000).

3. Top-SHAP Grouped Pareto Frontier

Rather than evaluating continuous sensor readings (voltage, temperature) which treat each run as an isolated singleton, points are aggregated over the top-4 discrete knobs ranked by SHAP. Produces 318 meaningful configuration clusters with observed rates tracking predicted risks exactly.

4. Constrained Bayesian Optimization

Optuna TPE searches the multi-dimensional design space against two LightGBM surrogates: risk and throughput. The throughput regressor trains exclusively on passing runs to measure true operating capability, enforcing an explicit penalised ≤ 2% risk ceiling.

5. Interactive Web Application (React 18 + Vite)

The frontend interface (in frontend/src/) connects via REST polling to FastAPI, organizing regression insights into 7 views:

1. Executive Summary

KPI cards (Runs, Fail Rate, Error Lines), Pass/Fail donut chart, Risk histogram, global SHAP chart, error taxonomy, and held-out ROC curve.

2. Failure Fingerprints

2D TruncatedSVD scatter projection of failure clusters, determinism table, masked template vs. raw log viewer, and one-click handoff to diff.

3. Trade-off Matrix

Interactive Pareto scatter with highlighted Peak Throughput, Knee, and Best-Safe operating points across 318 discrete configurations.

4. Recommendations

Optuna TPE search results, ranking parameter configurations that achieve peak throughput while staying below the 2% failure risk threshold.

5. Config Diff

Nearest-twin run analyzer comparing failing runs against closest passing counterparts (≥ 0.5 SD change threshold) to spotlight broken settings.

6. Run Explorer & Details

Full virtualized, searchable run table with pagination, field-level lift metrics, pipeline execution stage timings, and one-click JSON export.
